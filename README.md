# mailroom

**让 AI 替你盯着消息：收回来、判断这条属于哪个项目/任务、写进那个任务的时间线，然后用人话告诉你「谁找你、什么事、要不要回」。回复也从这儿发。**

支持两类来源：**明道云 / HAP**（私信、群、动态评论、任务通知、日程）和**邮箱**（IMAP/SMTP 或 Microsoft 365）。
数据落在你自己的 markdown 知识库里（[workmd](https://github.com/andyleimc-source/workmd) 那套结构），不进任何数据库。

零依赖：只用 node 内置模块加一个 python3 标准库脚本。没有构建，没有常驻进程，没有服务端。

---

## 它到底解决什么

工作里的消息散在四五个地方，而**每一条都属于某件事**。人脑替它们做归类，做得又慢又漏。

mailroom 把这件事拆成四步，其中三步是机器干的，判断那一步交给 AI，**发消息那一步永远要你点头**：

```
收 → 判 → 投 → 说
```

- **收**：把新消息取回来、按「一段对话」聚起来（同一个人连着说的几句算一段）
- **判**：AI 读一遍，判断这段属于哪个项目/哪个任务，写进那个任务的 `inbox.md`
- **投**：如果有别的 AI 会话正在管那个任务，把这段投进它的信箱
- **说**：剩下的用几句人话告诉你，要回的先把草稿拟好给你看

## 装

```bash
git clone <这个仓库> ~/coding/mailroom
ln -sf ~/coding/mailroom/bin/mailroom ~/bin/mailroom
mailroom setup      # 配置向导，问你几个问题
mailroom doctor     # 自检，看还缺什么
```

**要配的就两样，而且只配一样也能跑：**

### ① 明道云 / HAP（可选）

```bash
pip install hap-cli
hap auth login <你的组织>
```

⚠ **组织管理员要先打开 CLI 访问开关**（组织管理 → 安全 → 数据与访问 → CLI 访问策略），
否则所有命令都是 403。这不是你自己能修的，得找管理员。没开就先只用邮箱。

### ② 邮箱（可选）

- **IMAP/SMTP（推荐，任何邮箱都行）**：向导会问你服务器地址，然后让你自己跑一条命令把
  **客户端授权码**存进钥匙串（授权码不经过向导，进了程序就等于进日志、进终端回滚）：

  ```bash
  security add-generic-password -U -s mailroom-<账号代号> -a <你的邮箱> -w '<客户端授权码>'
  ```

  ⚠ 企业邮箱要的多半是后台生成的「客户端授权码」，不是登录密码；同时确认后台的
  IMAP/SMTP 服务已经开了。
- **Microsoft 365**：走 Graph。要自己在 Azure 注册一个公共客户端应用拿到应用 ID
  （向导会打印步骤），然后 `mailroom mail-login <账号代号>` 走设备码登录。
  ⚠ 有些租户不允许用户自行授权，那就得管理员点一次「代表组织授予管理员同意」，
  或者这个邮箱改走 IMAP。

**凭据一律存在系统钥匙串里，配置文件里只有条目名，没有值。**

配置文件在 `~/.mailroom/config.json`（**不在仓库里**：拉上游代码永远不会跟你的身份冲突，
你也不会手滑把账号信息提交上去）。每一项什么意思、不配会怎样，看 `config.example.json`。

## 用

平时挂着定时轮询就行：

```
loop 15m mailroom        # 在支持 /loop 的 AI 命令行里；m = 分钟，h = 小时，一律带单位
```

CLI 没有循环功能（agy、codex 都没有）就交给系统定时器，一次调用 = 一轮，
见下面「换一个 AI 命令行来跑」。

要手动看/修的时候：

```
mailroom            # 状态：登录态、上次收在什么时候、几段待判
mailroom doctor     # 自检
mailroom fetch      # 手动收一轮
mailroom pending    # 还有几段没判
mailroom out        # 翻发信总账：谁以你的名义发了什么、凭什么发
mailroom log 40     # 最近日志
mailroom test       # 自查
mailroom help       # 全部子命令
```

### 一轮里发生了什么

| 步 | 命令 | 干什么 |
|---|---|---|
| 收 | `node bin/fetch.mjs` | 取数 → 归档 → 聚段 → 把「等着判落点的段」连同你的项目/任务清单一起打出来 |
| 判 | `node bin/file.mjs '<JSON>'` | 把 AI 给的判定走原管线校验后写进 `inbox.md` |
| 发 | `node bin/send.mjs --seg <段id> --text "..."` | **唯一发送出口**（见下面「四条不能破的」） |
| 主动私信 | `node bin/send.mjs --to <人名> --text "..."` | 对方没先找你时用；两步，第一步只预览给确认码 |
| 翻账 | `mailroom out` | 谁以你的名义发了什么、凭什么发 |

判定的人是**对话里的那个 AI**，不是另起一个无人值守进程——怎么判写在 `skill/SKILL.md` 里，
那份说明 Claude / Codex / Gemini 系都读得懂。

## 数据在哪

代码在这个仓库，**数据全部在你的知识库**（配置里的 `knowledgeBase.root`）：

- `assets/hap-log/YYYY-MM.jsonl` —— 明道云消息原文，**唯一事实源**。`.md` 是由它整体重渲染的，别手改。
- `assets/mail-log/YYYY-MM.jsonl` —— **邮件**原文（跟上面分开：正文长、字段不同，混一起会把前者冲烂）
- `projects/P0X-*/tasks/T0X-*/inbox.md` —— 归位后的时间线，**这才是权威**

运行态在 `~/.mailroom/`：段索引、杂项状态、屏蔽规则 `mute.json`，加一份发信总账 `outbox.jsonl`。
前几个删了只是下一轮重收一次；**`outbox.jsonl` 删了就真没了**——它不是能从别处重建的缓存。
`inbox.md` 是权威，但账本上「哪个会话发的、凭什么发」这两栏 `inbox.md` 里没有。

### 屏蔽规则

`~/.mailroom/mute.json`，格式看仓库里的 `mute.example.json`。
每条 `{ pattern: 正则, kind: 'notice'|'user'|'group'|'post'|'mail', why: 人话 }`：

- ⚠ **不写 `kind` 就对所有候选生效，包括真人私信**——被吞掉只会表现成「没收到」。屏蔽平台播报一律写 `kind: 'notice'`。
- ⚠ 邮件规则还要写 `field: "from"` 或 `"subject"`，不写就拿正则去撞**整封邮件**。
  「退订」「newsletter」这种词一旦不限 `field` 就会撞进正文，把同事的真人来信静默吞掉。**踩过。**

### 换一个 AI 命令行来跑

整条管线里**只有「判这条消息归哪个任务」这一步按量烧钱**，其余全是本地脚本。
所以那一步是可换的：配置里 `runner.command` 填哪个 CLI 就用哪个（留 null = `claude`，老行为）。

```jsonc
// ~/.mailroom/config.json
"runner": {
  "command": ["agy", "--add-dir", "/绝对路径/你的知识库", "--dangerously-skip-permissions", "-p"]
}
```

也可以用环境变量临时顶掉：`MAILROOM_RUNNER='["codex","exec"]'`。

**没有 `/loop` 的 CLI 怎么定时**：交给系统定时器，一次调用 = 一轮。
macOS 用 launchd，Linux 用 systemd timer 或 cron。⚠ 别在会话里 `sleep` 死循环——
那要求终端一直开着，而且崩了就再也不跑了。

无人值守跑之前，这三件先在你那个环境里确认一遍，都是实打实栽过的：

1. **那个 CLI 在非交互模式下认不认项目。** agy 就不认：`-p` 模式下它没有工作区，
   默认落在自己的 scratch 目录里，读不到项目规则也读不到 skill，整轮空转还不报错。
   所以上面那条命令里 `--add-dir` 是硬要求。
2. **定时器给的环境极简。** `PATH`、代理变量、语言环境统统不继承，要在包装脚本里自己补。
   （agy 走 Google 的接口，某些地区的 IP 会被直接拒，代理不通这一轮就是空转。）
3. **失败要留得下证据。** 别发通知——通知只说明问题没解决。把真原因写进日志，
   下一轮自己再试；长期不通，翻日志一眼看得出来。

⚠ 还有一件跟人有关的：无人值守意味着**没人在旁边看那一轮的输出**。
🟡 和 🔴 那两档本来就要你点头，它们会安静地留在那儿等你；
真正要想清楚的是 🟢 那档要不要在无人值守时也放开自动回。

### 多台机器

收发水位线（收到哪封/哪条了）是**每台机器一份，不跨机同步**。两台同时跑，同一条消息会被各判一遍、
各回一遍，而明道云没有撤回接口。

所以只认一台主力机：配置里填 `topology.primaryHost`，别的机器上碰状态的子命令会自动 ssh 到主力机执行。
**只有一台机器就别填，那是默认，永远不转发。**

## 四条不能破的

1. **发送只有一条路。** 唯一出口是 `bin/send.mjs`，全仓库只有它会把 `MAILROOM_ROLE` 设成
   `approval-desk`，而 `send.mjs` 的运行时断言只认这一个值。两条 grep 测试盯着没有第二条路。

   ⚠⚠ 真出过事：3 条以本人名义发给同事的消息**绕过审批台**直接发了出去，
   根因就是「发送有第二条路」。所以这条不是洁癖，是事故换来的。

2. **明道云只走 `hap` CLI。** 401 就停下来提醒你重新登录，不许换通道兜底。

3. **发出去的每条都带身份声明**（`🤖 我是 X 的 AI Agent，…`），硬门在**发送**那一步，
   不在草拟那一步。声明和正文之间空一行——收件人要一眼分得清哪句是机器说的。

4. **邮件只要有一个外部收件人，就只存草稿，绝不发出去。**
   这道门是**物理**的，不是 if 判断：`connect/mail.mjs` 里 external 那条分支的花括号内
   压根没有发信函数的调用点（有一条测试把那对花括号之间的源码抠出来断言）。

   ⚠ 判「外不外部」取三个判据里最保守的那个，任一说外部就关门：
   ① 收信时按原信收件人算的标记（缺失/畸形一律当外部）；
   ② 这封回复的**实际收件人**（Reply-To 优先于 From）；③ From 本身。
   只信①的话，客户单独发一封给你时原信收件人全是内部的，就会直发给客户。

### 三档：哪些要问你，哪些不用

| 档 | 什么内容 | 怎么发 |
|---|---|---|
| 🟢 自己发 | 纯回执 · 有据可查的事实回答 · 约时间的确认 | `--auto "<判成🟢的理由>"`，**默认整档关闭**，要在配置里开 |
| 🟡 发完报备 | 对内、有实质内容但**不含任何承诺** | `--why "<凭什么不问你就发>"`，不给当场拒发 |
| 🔴 等你那句「发」 | 承诺时间/资源/交付 · 对外 · **群消息** · 催办 · 说别人做错了 · 金额法务 · 第一次联系某人 | 两步确认码 |

🟢 那一档的客观条件焊在 `autosend.mjs` 里由代码验（字数、频次、时段、是不是群…），
「这句是不是纯回执」才轮到 AI 判，而且只在代码那几条全过之后才算数。
每条自动发的都写进总账，`mailroom out` 能翻。

### 发出去之前会自动重收一轮

你手上那份消息可能已经过期了。`send.mjs` 在真发的那一下会自己再收一轮，只要**同一条线**
（同群 / 同一个人的私信 / 同一封邮件的线程）上有新消息，就当场拦下、把新消息列出来，一个字都不发。

⚠ 这道门是事故换来的：15:37 拿到一句「素材可以用于官网首页」，15:45 回了「用在首页」——
而对方 15:44 已经在同一个群里说了另一个地址。回复发出去才发现说岔，而且撤不回。
